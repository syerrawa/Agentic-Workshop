- (direction) Sachin asked to turn INTENT.md into a spec with slug epic-1; input is complete, so distilled directly (no elicitation).
- (decision) Why: vision to realize. Epics 2 and 3 are specced against an Epic 1 schema and loader that do not exist yet; this epic creates both.
- (capability) CAP-1 intent: a triage decision is a JSON object with category, priority, route, rationale; anything else is rejected. success: valid decision accepted; bad enum value, missing field, extra field, or non-sentence rationale rejected with an error naming the field.
- (capability) CAP-2 intent: one command loads seed/tickets.csv and seed/customers.csv into app.db as tables tickets and customers with the CSV columns. success: uv run python load_seed.py creates both tables, row counts match the CSVs, and mcp/triage_server.py get_ticket/get_customer_history queries return rows.
- (capability) CAP-3 intent: re-running the loader gives the same database. success: two consecutive runs leave identical tables and row counts, no duplicates.
- (constraint) Python 3.12+, managed with uv; packages added with uv add.
- (constraint) seed/ is read-only; loader reads it and never writes to it.
- (constraint) No network calls and no API keys in this epic.
- (constraint) mcp/triage_server.py is read-only and queries tickets(ticket_id, customer_id, created_at, text) and customers(customer_id, name, plan, open_tickets); those names must keep working.
- (constraint) app.db is git-ignored and never committed.
- (decision) Non-goals from INTENT.md: the agent, the MCP tools, evals, any user interface.
- (assumption) Anything else is rejected includes extra fields beyond the four.
- (assumption) Loader rebuilds tables from scratch each run (drop and recreate) to guarantee idempotence.
- (assumption) open_tickets is stored as an integer; other columns as text.
- (question) How strictly is one-sentence rationale checked: non-empty single sentence (one terminal punctuation mark) or just non-empty string?
- (decision) Schema's module location and library are left to the build; pydantic is already a dependency.
- (decision) CAP-1 success narrowed to empty rationale for now; one-sentence strictness held as open question rather than invented.

- (event) Self-validate pass 2 (preservation): PASS.
